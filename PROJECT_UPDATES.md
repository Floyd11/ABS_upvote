Этот файл содержит всю необходимую информацию для новой языковой модели (LLM), чтобы быстро погрузиться в контекст проекта, понять его архитектуру, структуру и последние изменения, и продолжить работу без потери контекста.

## 1. Project Overview (Обзор проекта)
**Abstract Upvote Bot** — это децентрализованное приложение, которое автоматизирует ежедневные голосования в экосистеме блокчейна Abstract L2. Вместо того, чтобы пользователи голосовали вручную каждый день, бот использует **Native Account Abstraction** и **Abstract Global Wallet (AGW)** Session Keys, чтобы голосовать от их имени за разрешенные контракты, не имея прямого доступа к их средствам.

## 2. Architecture & Tech Stack (Архитектура и Стек)
- **Frontend**: Next.js (App Router), React, Tailwind CSS, AGW React SDK, Privat/Privy интеграция для аутентификации. Работает на порту `3000`.
- **Backend API**: Python FastAPI. Отвечает за аутентификацию (JWT), сессии, планировщик задач (Scheduler), очереди и опросы. Работает на порту `8001`.
- **Transaction Service (tx-service)**: Node.js сервис (порт `3010`), использующий `@abstract-foundation/agw-client`. Отправляет блокчейн-транзакции с использованием временных сессионных ключей формата EIP-712.
- **Database**: PostgreSQL (порт `5433` на хосте, `5432` в контейнере), Alembic для миграций. Схема: `upvote_bot`.
- **Инфраструктура**: Docker Compose, Nginx в качестве Reverse Proxy (с HTTPS через Certbot).

## 4. Как это работает (Core Logic)
1. Пользователь заходит на сайт, проходит логин через AGW.
2. Генерируется **Session Key** с ограниченными политиками (Policy): вызов только `voteForApp(uint256)` на целевой контракт, лимит комиссии `0.01 ETH`. Запрет на вывод средств.
3. Сессионные ключи шифруются симметричным алгоритмом `Fernet` (через `ENCRYPTION_KEY`) и сохраняются в PostgreSQL.
4. Фоновый планировщик (`scheduler.py`) запускается каждый день и итерируется по пользователям:
   - Внутри эпохи каждому пользователю формируется детерминированная очередь проектов для голосования.
   - Транзакции проксируются в `tx-service`.
5. `tx-service` собирает транзакцию с нужной кастомной EIP-712 подписью и отправляет ее в Abstract-ноду.

## 5. Последние изменения (Recent Updates & Fixes)
При переносе контекста учтите следующие недавние исправленные баги и внедренные фичи:
* **App Rotation & Failure Handling (Ротация приложений):** Переписан `scheduler.py`. Если голосование за `appId` проваливается (например, контракт отклонил), система автоматически пропускает этот `appId` и переходит к следующему доступному в очереди в тот же день, вместо постоянного ретрая одного и того же приложения.
* **Polling Async Refactor (Асинхронные задачи):** Запросы на анализ (например, Polymarket URL) приводили к таймаутам (Failed to fetch) из-за последовательных вызовов. Внедрен асинхронный polling: `/analyze` теперь сразу возвращает `task_id`, а фронтенд отправляет запросы на статус в `/task/{task_id}`.
* **Fixing Registration & 422 Errors:** Исправлена сериализация `BigInt` значений между Frontend, Python Backend и Node.js tx-service. Решены проблемы "Registration failed" и ошибки HTTP 422.
* **Fixing Vote Transaction Errors:** Исправлены ошибки авторизации `401 Unauthorized` и `500 Internal Server Error` между backend и `tx-service`, добавлены валидные зашифрованные конфигурации сессий в payload.
* **Refactoring Voting Logic:** Граница эпохи перенесена на **15:00 UTC** для синхронизации с блокчейном. Добавлен асинхронный retry механизм со ступенчатой задержкой (15-30 минут).
* **SIWE (Sign-In with Ethereum) Fixes:** Исправлен флоу логина и выравнивание (padding до 32 байт) подписей для AGW контрактов. Отказ от жесткого сброса сессии (logout) при неудачной подписи — добавлена кнопка "Retry Sign-In".
* **Persistent Database Storage (Сохранность данных):** В `docker-compose.yml` добавлен `volumes: pgdata` для контейнера `db`, устраняющий проблему потери SQL-данных пользователей и ключей сессий при перезапуске (down/up) контейнеров базы данных. Ошибка 404 и 500 для старых пользователей при рестарте проекта больше не возникнет.
